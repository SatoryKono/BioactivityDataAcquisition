# CI Evidence Retention Policy

## 1. Overview
This policy defines the retention and immutability requirements for CI timing telemetry, architecture governance measurements, and docker publishing records generated by BioETL.

## 2. Policy Requirements

- **Immutable Append-Only Storage (Policy-Level Constraint):**
  Technically, GitHub repositories cannot fully guarantee true WORM (Write-Once Read-Many) without platform-level enforcement. At the governance policy level, the evidence stored in `reports/test-telemetry/`, `reports/governance/`, and related paths must be treated as append-only. Existing snapshots must not be modified or silently overwritten. If schema version updates are necessary, new files must be generated alongside the old ones.

- **Data Fingerprinting:**
  All telemetry evidence files must include the complete SHA-256 footprint of the inputs (e.g. source checkout manifest, test coverage mapping) and the exact Git SHA (main/tested) at the time of execution.

- **Retention Window:**
  - Active/Working CI evidence must be retained for **≥30 days**.
  - Historical Archive copies (for baseline measurement regressions) must be retained for **≥90 days**. If platform constraints force shorter retention, the historical dossier must be securely committed to an external permanent storage layer or an isolated branch prior to eviction.

- **Stakeholder Transparency (Receivers):**
  Evidence outputs are distributed to the CI Governance Owner, Security Auditors, and Tech Debt Reviewers. `reports/governance/ci-baseline.json` records tool versions and SHA-256 hashes of the workflow inventory. It does not store timing measurements, so those hashes do not recompute timings. Duration evidence stays in `reports/test-telemetry/`.

## 3. Schema Enforcement
The structure of the `ci-baseline` artifact is governed by its explicit JSON Schema (`reports/governance/ci-baseline.schema.json`), capturing execution environment tool versions and exact pipeline topologies.
