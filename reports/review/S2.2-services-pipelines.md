### S2.2-01 — Неканоническая сериализация JSON-поля классификаций

- **Local severity:** MEDIUM
- **Evidence:** `src/bioetl/application/pipelines/chembl/target_protein_classification_summary.py:224-230`
- `_serialize_classifications()` формирует persisted JSON-подобное поле `protein_classifications` через `json.dumps(..., sort_keys=False, separators=(",", ":"))`.
- Это расходится с обязательной canonical JSON policy: JSON-like поля Silver/Gold должны сериализоваться с `sort-keys=True` (`docs/00-project/RULES.md:490-495`).
- Текущий helper строит dict в стабильном локальном порядке, поэтому непосредственная process-to-process нестабильность не доказана. Дефект состоит именно в несоответствии каноническому контракту и риске разных байтов/`content_hash` при появлении альтернативного producer-а или изменении порядка построения payload.
- **Recommendation:** использовать общий canonical JSON serializer либо как минимум `sort_keys=True`; зафиксировать exact serialized value regression-тестом.

### S2.2-02 — Ошибки включённой DQ-reporting цепочки сводятся к `None`

- **Local severity:** MEDIUM
- **Evidence:** `src/bioetl/application/services/dq_report_models.py:14-23`, `src/bioetl/application/services/_dq_report_layer_flows.py:123-141`, `src/bioetl/application/services/dq_report_service.py:97-112`
- `_DQ_REPORT_ERRORS` заканчивается базовым `Exception`, поэтому перечисленные перед ним типы не ограничивают catch surface: практически любая обычная ошибка analyzer/writer перехватывается, логируется и превращается в `None`.
- `DQReportResult` затем возвращает `gold_enabled=True` одновременно с `gold_report_path=None`, без типизированного failure disposition. Это затрудняет вызывающему коду отличить сбой обязательного отчёта от штатного skip.
- Существующие тесты прямо закрепляют это поведение: `tests/unit/application/services/test_dq_report_generation_mixin.py:553-590` ожидают `None` при сбое Gold analyzer и writer.
- Это не доказательство обхода strict Pandera validation на Gold write path: DQ report flow отделён от writer validation. Риск ограничен fail-open семантикой включённой reporting/observability цепочки.
- **Recommendation:** убрать `Exception` из `_DQ_REPORT_ERRORS`; возвращать типизированный outcome (`generated`/`skipped`/`failed`) или пробрасывать ошибку согласно явной per-layer policy.

### S2.2-03 — Annotation-only gate выявляет незакрытые typing gaps

- **Local severity:** LOW
- Полный `ruff` по штатному набору правил проходит, но отдельный `--select ANN` выявляет 21 нарушение: 19 `ANN401` и 2 отсутствующих return annotations.
- Конкретные недостающие annotations: `src/bioetl/application/pipelines/chembl/target_helpers.py:192` (`ANN205`) и `src/bioetl/application/pipelines/common/publication_transformer_context.py:146` (`ANN201`).
- В scope найдено 280 строк с `Any`; значительная часть снабжена объяснениями для heterogeneous JSON/DataFrame contracts, поэтому количество само по себе не трактовалось как дефект.
- **Recommendation:** закрыть две отсутствующие return annotations и постепенно заменять `Any` узкими protocol/type aliases на публичных application boundaries, не расширяя exclusions.
