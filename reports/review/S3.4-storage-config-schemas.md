## Findings

### LOW: `datetime.now(UTC)` in metadata builders and writers (6 instances)

**Files:**
- `metadata_builder.py:304` -- `SilverMetadataBuilder.build_merged_metadata()`
- `metadata_builder.py:425` -- `GoldMetadataBuilder.build_fallback_metadata()` (fallback: `now = ingestion_ts or datetime.now(UTC)`)
- `metadata_builder.py:530` -- `GoldMetadataBuilder.build_merged_metadata()`
- `gold_writer.py:428` -- `_write_gold_merged_metadata()` (completed_at for merged data)
- `silver_writer.py:602` -- `write_silver()` (started_at for duration tracking)
- `silver_writer.py:787` -- audit fallback timestamp

**Rule:** Determinism (ADR-014)
**Severity:** LOW
**Analysis:** These are all in fallback code paths:
- `metadata_builder.py` methods are only invoked when `MetadataCoordinator` is not available (backward compatibility)
- `silver_writer.py:602` captures `started_at` for internal duration measurement, which is a reasonable use of current time
- `silver_writer.py:787` is a fallback with an explicit warning log
- `gold_writer.py:428` is for merged metadata where no application timestamp is available

The primary code paths (when MetadataCoordinator is configured, which is the production path) receive timestamps from the application layer. The `bronze_writer.py` explicitly documents this pattern: "avoids datetime.now() per ADR-014".

**Recommendation:** Consider adding `# ADR-014: fallback only, prefer application-provided timestamp` comments at each `datetime.now()` usage to make the intent explicit.

### INFO: `config_loader.py` is large (700+ lines)

The file handles multiple config formats (legacy, unified entity ADR-039, convention-based ADR-029) with extensive normalization logic. It is well-structured with small helper functions but could benefit from further decomposition if more formats are added.
