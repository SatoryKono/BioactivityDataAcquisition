### S1.2-001 — HIGH — Normalization profile identity is process-dependent for valid callable normalizers

- **Local severity:** HIGH (deterministic identity / exact-replay compatibility risk).
- **Rules:** `RULES.md` §4.3 and §6.1; Qodo `718014`, `717993` (`QG-DET-001`, Qodo severity `UNSPECIFIED`).
- **Evidence:** `src/bioetl/domain/normalization/profiles/base.py:39`, `src/bioetl/domain/normalization/profiles/base.py:49`, `src/bioetl/domain/normalization/profiles/base.py:187`, `src/bioetl/domain/normalization/profiles/base.py:271`.
- **Current behavior:** `_normalizer_ref()` falls back to `repr(normalizer)` when a callable has no instance-level `__module__`/`__qualname__`. A callable object is permitted by the public `FieldNormalizer = Callable[..., object]` contract, and its default `repr()` embeds a process-specific memory address. That value is included in both `FieldRuleIdentity.compatibility_hash` and `NormalizationProfileIdentity.profile_hash`.
- **Impact:** the same normalization profile can publish a different `normalization_profile_hash` in different processes. This creates false compatibility drift and can prevent or misclassify exact replay even when code/config are unchanged.
- **Verification 1 — code trace:** `_normalizer_ref()` -> `FieldRule.identity` -> `NormalizationProfile.identity` shows the `repr()` value entering the persisted SHA-256 identity.
- **Verification 2 — runtime reproduction:** three fresh Python processes produced three different normalizer references and hashes for the same callable class:

  ```text
  <__main__.C object at 0x7a1b16ed97f0> 4d11f90d...
  <__main__.C object at 0x7ff9889117f0> df5412c4...
  <__main__.C object at 0x7c01c57a97f0> a73013b0...
  ```

- **Verification command:**

  ```bash
  for i in 1 2 3; do .venv/bin/python -c 'from bioetl.domain.normalization.profiles import FieldRule, NormalizationProfile; C=type("C",(),{"__call__":lambda self,value:value}); p=NormalizationProfile(profile_name="x",field_rules={"x":FieldRule("x",normalizer=C())}); print(p.field_identity("x").normalizer_ref,p.identity.profile_hash)'; done
  ```

- **Remediation direction:** require an explicit stable identity for callable objects, or derive it from the callable class (`type(normalizer).__module__` + `__qualname__`) plus a canonical, validated state payload; reject unsupported callable state instead of falling back to `repr()`.

### S1.2-002 — HIGH — `EffectiveConfigArtifact` is only shallow-frozen and its immutable snapshot can change after hashing

- **Local severity:** HIGH (reproducibility/control-plane evidence corruption risk).
- **Rules:** Qodo `718014`, `717993` (`QG-DET-001`, Qodo severity `UNSPECIFIED`); immutable effective-config contract in `docs/04-reference/components/config-runtime-artifacts.md`; reproducibility evidence requirements in `RULES.md` §7.
- **Evidence:** `src/bioetl/domain/control_plane/effective_config_artifact.py:80`, `src/bioetl/domain/control_plane/effective_config_artifact.py:92`, `src/bioetl/domain/control_plane/effective_config_artifact.py:113`, `src/bioetl/domain/control_plane/effective_config_artifact.py:139`, `src/bioetl/domain/control_plane/effective_config_artifact.py:168`.
- **Current behavior:** the nested snapshot dataclasses and `EffectiveConfigArtifact` use `frozen=True`, but retain caller-owned mutable dictionaries/lists (`config_data`, override maps, `source_refs`, contract/DQ collections) without defensive copying or deep freezing. The existing immutability test only checks reassignment of `artifact_id` (`tests/unit/domain/control_plane/test_effective_config_artifact.py:551`) and does not test nested mutation.
- **Impact:** configuration payloads may change after `resolved_config_hash`, `effective_config_hash`, `source_fingerprint`, or `artifact_id` were computed. The persisted semantic artifact can then disagree with its identity anchors, weakening exact-replay verification and audit evidence.
- **Verification 1 — source/test inspection:** mutable collection fields are stored unchanged in frozen dataclasses; `__post_init__()` normalizes timestamps/hash text but does not copy/freeze nested payloads.
- **Verification 2 — runtime reproduction:** mutating the caller-owned `cfg` after construction changes both frozen snapshot views; `source_refs.append(...)` also succeeds.

  ```text
  {'mode': 'safe'}
  {'mode': 'mutated'} ['not-a-ref']
  ```

- **Verification command:**

  ```bash
  .venv/bin/python -c 'from bioetl.domain.control_plane.effective_config_artifact import ConfigResolutionPolicy,EffectiveConfigArtifact,EffectiveExecutionConfig,ResolvedConfigSnapshot,RuntimeOverrideSnapshot; cfg={"mode":"safe"}; a=EffectiveConfigArtifact(artifact_id="a",pipeline_name="p",pipeline_kind="standard",source_refs=[],resolution_policy=ConfigResolutionPolicy(),resolved_config=ResolvedConfigSnapshot(config_type="standard",config_data=cfg,config_hash="h"),runtime_overrides=RuntimeOverrideSnapshot(),effective_execution_config=EffectiveExecutionConfig(config_data=cfg,effective_hash="eh"),resolved_config_hash="h",effective_config_hash="eh",source_fingerprint="f"); print(a.resolved_config.config_data); cfg["mode"]="mutated"; a.source_refs.append("not-a-ref"); print(a.resolved_config.config_data,a.source_refs)'
  ```

- **Remediation direction:** deep-copy and freeze all semantic payloads at each snapshot boundary (immutable mappings/tuples), and add regression tests for caller-alias and nested/direct mutation.
