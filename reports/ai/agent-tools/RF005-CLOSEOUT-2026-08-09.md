# RF-005 platform and optional vendor tooling closeout

Date: 2026-08-09

Owner: `platform/setup scripts`

Issues: #8470, #8469, #8408, #8409, #8410, #8411, #8412, #8431

## Outcome

- Platform-dependent command and path handling is centralized in
  `scripts/engineering/common/platform.py` and covered by unit tests.
- MCP compatibility wrappers are generated from the canonical shared-server
  catalog for Windows and POSIX, with drift checking in CI.
- AgentDebugX and ProofAgent Harness are exact, lock-backed, opt-in extras. They
  remain absent from the default BioETL environment and core import graph.
- Both packages resolve, install from wheels, report `AVAILABLE`, and execute
  through the safe adapter on fresh WSL/Linux and native Windows environments.
- Vendor execution is subprocess-only, bounded to approved fixture/report
  roots, redacted, timeout-controlled, deterministic or no-upload, and unable
  to advance Proof-or-Stop or any BioETL lifecycle state.
- The joint utility pilot found no safety blocker. AgentDebugX is retained as an
  opt-in deterministic diagnostic. ProofAgent is retained with constraints as
  advisory evidence only.
- No `.env` file was changed and no technical-debt budget was increased.

## Closeout policy

Optional-tool absence, incompatibility, timeout, malformed output, or vendor
failure remains advisory and cannot fail core BioETL execution. Vendor output is
review evidence only. Native tests and policy-required Proof-or-Stop receipts
remain authoritative.
