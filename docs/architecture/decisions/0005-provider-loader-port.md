# Provider Loader Port

## Status

Superseded

## Context

Application слой напрямую зависел от инфраструктурного загрузчика провайдеров (`load_provider_registry`), из-за чего нарушались границы слоев и усложнялась миграция на новые реализации. Для безопасного перехода вводился порт с временным фиче-флагом.

## Decision

- Ввести доменный порт `ProviderLoaderProtocol` для загрузки реестра провайдеров.
- Реализовать адаптер `ProviderLoaderImpl` в infrastructure, повторяющий прежнюю логику YAML-лоадера.
- Глобальный фиче-флаг `enable_provider_loader_port` больше не используется: порт включён всегда, а падение конфигурации обрабатывается через явные зависимости.
- Контейнер и orchestration получают загрузчик через порт; инфраструктурные детали остаются в composition root (CLI/REST/MQ).
- Rollback: ранее реализовывался через выключение фиче-флага; теперь замещён явным управлением зависимостями.

## Consequences

- Границы слоев выровнены: domain объявляет контракт, infrastructure дает реализацию, application использует порт.
- Миграция завершена, флаг удалён; тесты и конфиги, опиравшиеся на него, больше не нужны.
- Контейнеры и orchestrator всегда работают через порт и явные зависимости, глобальный реестр не используется.
