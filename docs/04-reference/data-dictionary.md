BioETL's Silver and Gold layers. Fields are derived from the canonical schema
definitions in `configs/entities/{provider}/{entity}.yaml`.

For publication-specific fields (191 fields × 5 providers) see the dedicated
[Publication Fields Reference](publication-fields-reference.md).

## 1. System Fields (all entities)

Every Silver/Gold entity includes the following system-managed fields. They are
generated by the pipeline and **MUST NOT** be set by provider adapters.

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| `entity_id` | `string` | No | Surrogate key — SHA-256 hash of business keys. Stable across re-runs. |
| `content_hash` | `string` | No | Hash of all business fields. Used for deduplication and change detection. |
| `_run_id` | `string` | No | UUID of the pipeline run that wrote this record. |
| `_run_type` | `string` | No | Run mode: `full`, `incremental`, or `backfill`. |
| `_source_batch_id` | `string` | Yes | Bronze batch file identifier for this record's origin. |
| `_ingestion_ts` | `datetime` | No | UTC timestamp when the record was written to Silver. |
| `_index` | `integer` | Yes | Position of the record within its source batch. |

## 2. ChEMBL Entities

drug-like properties. Rate limit: 3 req/sec (public).

## 6. Naming Conventions

Field names in BioETL follow these rules:

| Convention | Rule | Example |
|-----------|------|---------|
| **snake_case** | All Silver/Gold field names use snake_case | `standard_value`, `molecule_id` |
| **System prefix `_`** | System-managed metadata fields start with `_` | `_run_id`, `_ingestion_ts` |
| **FK suffix `_id`** | Foreign key fields end with `_id` | `assay_id`, `target_id` |
| **Boolean prefix** | Boolean fields use descriptive names | `withdrawn_flag`, `therapeutic_flag` |
| **JSON suffix** | Fields containing JSON arrays/objects | `cross_references`, `synonyms` |
| **PK convention** | Primary key is the provider's canonical identifier | `activity_id`, `accession`, `cid` |

### System vs. Business Fields

- **System fields** (prefix `_` or `entity_id`/`content_hash`): Managed by the
  pipeline framework. Do not appear in source API responses.
- **Business fields**: Derived from provider API responses via the extraction
  and transformation stages.
