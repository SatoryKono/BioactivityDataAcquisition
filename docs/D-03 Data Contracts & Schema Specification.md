# D-03 Data Contracts & Schema Specification

Краткий обзор нормативных правил, жизненного цикла и требований по публикации data contracts (особенно Gold/Silver) вместе с проверками и миграционными обязанностями.

## Цель документа

1. Зафиксировать, какие артефакты являются «source of truth» для контрактов и схем (кодовые контракты, Pandera/JSON Schema, index-реестры).  
2. Описать версионирование (SemVer + файл/импорт) и модель совместимости (BACKWARD/ FORWARD/ FULL).  
3. Сформулировать workflow изменения контрактов: обязательные ADR, dual-service windows, cutover/rollback criteria, deprecation window.  
4. Уточнить контрольные точки: CI-gates (schema generation/check, parity diff), contract testing и обновление changelog/notifications.

## Источники и артефакты

| Артефакт | Где находится | Статус |
| --- | --- | --- |
| Исходные Gold контракты | `src/bioetl/domain/contracts/gold/*.py` | Source of truth |
| Публикации JSON Schema | `docs/04-reference/contracts/gold/*.json` | generated by `scripts/schema/generate_schema_artifacts.py` |
| Silver schema | `src/bioetl/domain/schemas/{provider}/{entity}.py` + Pandera |
| Schema registry | `src/bioetl/domain/schemas/generated/registry.py` (из `configs/entities`), список в `docs/04-reference/contracts/gold-schemas.md` |
| Contracts index | CI-validaция parity между list и exports |
| Contract tests | `tests/contract/` + `monthly contract-tests.yml` workflow с `BIOETL_LIVE_API_TESTS=true` |

Скрипт `scripts/schema/generate_schema_artifacts.py` запускается с `--check` в CI и блокирует пайплайн при расхождении между кодом и экспортами.

## Версионирование и публикуемая нотация

- SemVer (major.minor.patch) применяется к Gold контрактам.  
- Патч-уровень сохраняется в `$version`, но имя файла использует только `v{major}.{minor}` (например, `crossref_publication_v1.0.json`), чтобы patch-изменения не ломали ссылки.  
- Классификация изменений:
  - `major`: удаление/переименование поля, изменение типа, изменение PK-договора.  
  - `minor`: добавление nullable/optional полей, non-breaking расширения.  
  - `patch`: документация/метаданные, не влияющие на shape (публикуется без смены имени файла, но описывается в changelog).  
- Таблица версионирования внутри документа описывает: SemVer-описание, путь (X.Y vs X.Y.Z), риски и статус (см. разделы ниже).

## Совместимость и dual-service

1. Минимальный уровень совместимости — BACKWARD: новые контракты читают старые данные в пределах окна поддерживаемости.  
2. Для критичных витрин (core analytics) требуется FULL совместимость в период dual-service (одновременная публикация старой и новой версии + monitoring adoption).  
3. Deprecation window = `max(14 календарных дней, 2 релиза)` по ADR-036.  
4. Cutover возможен только при соблюдении: adoption > 90%, parity checks, отсутствие critical DQ alerts 7 дней, предусмотрены rollback критерии.  
5. PK-перемены/renames требуют migration plan (add new PK, backfill, dual-write, drop old column уже в major release) и impact assessment с документацией.

## Workflow изменения Gold/Silver контрактов

1. Определить уровень изменения (major/minor/patch) и включить ADR при major/legacy-breaking.  
2. Обновить код: Pandera/contract класс, возможно pipeline schema.  
3. Запустить `scripts/schema/generate_schema_artifacts.py` (+ `--check` в CI) для регенерации JSON/registry.  
4. Обновить published exports, changelog entry, index parity.  
5. Major изменения:
   - PR label `breaking-change`.  
   - ADR с decision/migration plan/rollback/adoption criteria.  
   - Dual-service policy (2 релиза, dual-write, parity).  
   - Уведомление consumers (канал `#platform-governance` или аналогичный, текущий канал уточняется при релизе).  
6. Minor изменения: update changelog, API docs, optional release note.  
7. Patch changes: объявляется как metadata/docs, explicit mention в changelog под `patch`.

## Validation gates и tests

- `uv run python -m scripts.schema generate_schema_artifacts --check`  
- `uv run python -m pytest tests/contract/ -k <contract>` + `monthly contract-tests.yml` (bioetl contract CI в canonical repo).  
- `scripts/schema/check_contract_parity.py` или аналогичный parity diff (описание diff export mandatory).  
- Schema drift Info/Critical SLA: Critical drift owner уведомляется, 48h remediation, нерешённый drift блокирует релиз.  
- Contract tests должны покрывать `chembl`, `pubchem`, `uniprot`, `pubmed`, `crossref`, `openalex`, `semanticscholar`.

## Compliance и governance

| Требование | Описание |
| --- | --- |
| ADR + migration plan | Major (breaking) изменения требуют ADR (decision + migration plan + rollback criteria) и documentation. |
| Dual-service | Deprecation window (14 дней или 2 релиза) + parity + 0 critical DQ + adoption > 90% перед cutover. |
| Labels/notifications | Breaking PR обязательно с `breaking-change`; consumers уведомляются указанным каналом. |
| CI enforcement | diff contract -> artifact; parity diff публикуется как артефакт или chatops-уведомление. |
| Secret/registry consistency | JSON Schema `$schema` + canonical `$version`; exports не содержат secrets. |

## Критерии завершения

1. Gold контракт сгенерирован, JSON Schema в `docs/04-reference` совпадает с кодом (diff=0).  
2. Contract test suite проходит (CI + manual).  
3. Changelog/ADRs обновлены, notifications trigger выполнен.  
4. CT scans: dual-service window соблюдён, adoption metrics (>=90%) + parity + DQ ticks clean.  
5. Dokumentation ack: `docs/04-reference/contracts/gold-schemas.md` + D-02 handbook + D-05 config spec обновлены при необходимости.
