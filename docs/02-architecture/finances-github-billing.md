# GitHub Billing Financial Analysis
## Ожидание данных
Эта документация описывает процесс сбора и анализа финансовой информации (GitHub Billing) согласно issue #12351.
В настоящее время выгрузка ожидается от участника с соответствующими правами (`billing-доступ`).
## Исходные периоды
- Исходный срез: `2026-09-01..2026-09-30` (ОЖИДАЕТСЯ, не after)
- Исходный срез: `2026-10-01..2026-10-19` (ОЖИДАЕТСЯ, неполный месяц, не after)
Октябрьский срез не доказывает эффект оптимизаций, проведённых позже. Сопоставимый after для F1 (#12366) согласуется отдельно: неполный месяц, объём запусков и артефактов, валюта.
## Схема выгрузки
Для атрибуции по workflow нужен Detailed usage report из веб-интерфейса GitHub.
Сводный отчёт (Summarized usage report) не содержит `workflow_path`, и валидатор его отклоняет.
Столбец `workflow_path` обязателен; в отдельной строке он может быть пустым.
Выгрузка должна представлять собой CSV-файл с обязательными полями:
- `date`
- `product`
- `sku`
- `repository`
- `workflow_path`
- `quantity`
- `unit_type`
- `gross_amount`
- `discount_amount`
- `net_amount`
- `currency`
`currency` обязателен в каждой строке. Отсутствие столбца не подставляется как USD.
Денежные поля `gross_amount`, `discount_amount` и `net_amount` читаются как `Decimal`.
`float` для этих полей отклоняется.
Для каждой строки должно выполняться `gross_amount - discount_amount = net_amount`.
Повторяющиеся имена столбцов и лишние ячейки в строке отклоняются.
Пустой файл и CSV только с заголовком отклоняются: это не нулевые расходы.
`calculate_totals` и `extract_workflow_attribution` суммируют строки только когда валюта
каждой строки совпадает с явной валютой отчёта.
Расходы Actions на runner попадают в `actions_compute`, если SKU содержит `compute`
или официальное имя runner (`Actions Linux`, `Actions Windows`, `Actions macOS`).
SKU со `storage` в эту категорию не входит.
`Actions storage` и `Packages storage` попадают в `shared_storage`.
`Actions cache storage` и `Actions custom image storage` в этот пул не входят.
Атрибуция workflow использует пару `(repository, workflow_path)`. Одинаковый путь
workflow в разных репозиториях учитывается раздельно. Пустой `repository` не
смешивается с названным репозиторием.
Для программного валидатора и обработки этих данных смотрите:
- `scripts/engineering/finances/github_billing_schema.py`
- `scripts/engineering/finances/github_billing_validator.py`
- `scripts/engineering/finances/github_billing_pipeline.py`
## Конфиденциальность
Финансовые строки, персональные сведения об оплате и сама выгрузка НЕ ДОЛЖНЫ быть опубликованы в public issue, PR, общедоступном artifact или вместе с техническим отчётом.
Разрешена публикация только согласованной обезличенной сводки/статуса.

## Неопределённость до выгрузки

`reports/engineering/finances/billing_manifest.json` остаётся в статусе `AWAITING_DATA`.
Оба исходных периода `PENDING`, контрольная сумма `PENDING`, финансовый эффект не установлен.
`currency` и `filters_applied` равны `null`: это неизвестные свойства отсутствующей выгрузки, а не доказанные USD и пустые фильтры.
Схема манифеста `1.1` отзывает незасвидетельствованные значения `currency: USD` и `filters_applied: "None"` схемы `1.0`.
Timezone, дата выгрузки, источник, версия нормализации и команда расчёта не заполняются без неизменяемого оригинала.
Оригинал выгрузки не переписывается ради нормализованной схемы. Недоступное поле остаётся отсутствующим, а не нулём.
Дополнительный период сохраняется отдельно и не подменяет исходные окна.
`Actions cache storage` и `Actions custom image storage` остаются вне `shared_storage`, даже если метка product говорит Shared Storage.
`shared_storage` не приписывается целиком Actions: в нём вместе лежат Actions storage и Packages storage.
Copilot и LFS остаются строками выгрузки, но не входят в эффект этой программы.
Пустой `workflow_path` у Actions compute становится `unattributed`. Неизвестный repository или workflow не назначается вымышленно.
Неизвестный SKU попадает в `other` и не получает workflow-атрибуцию.
Сумма категорий равна сумме `net_amount`. Runner-minutes не заменяют `net_amount`. Нулевой compute двух запусков не доказывает нулевой месячный счёт.
При нулевом baseline `net_amount` относительная денежная экономия не вычисляется. Десятикратная экономия не заявляется.
Ошибки валидатора называют ограничение и не включают значения ячеек.
Персональные assignees не назначены. Владелец billing-доступа и подтверждение расчёта отсутствуют.
Issue #12351 не разрешает доступ к платёжным аккаунтам. Тарифы, бюджеты, оплата, Copilot, LFS и настройки Actions не меняются.
