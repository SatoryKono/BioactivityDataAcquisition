# Доменный слой

Доменный слой (`bioetl.domain`) содержит чистую бизнес-логику проекта и реализует паттерны **DDD** (Domain-Driven Design — предметно-ориентированное проектирование). Этот слой не имеет зависимостей от внешних систем и I/O.

---

## DDD-компоненты

### Ports (Порты)

**Расположение:** `domain/ports/`

Protocol-интерфейсы для инверсии зависимостей (Dependency Inversion). Определяют контракты, которые должны реализовывать адаптеры в инфраструктурном слое.

Примеры портов:
- Порт хранилища — операции чтения/записи данных
- Порт HTTP-клиента — взаимодействие с внешними API
- Порт наблюдаемости — логирование, метрики, трассировка
- Порт блокировок — управление конкурентным доступом

### Aggregates (Агрегаты)

**Расположение:** `domain/aggregates/`

Доменные агрегаты с защитой инвариантов. Агрегат — это кластер связанных объектов, которые рассматриваются как единое целое при изменении данных. Корень агрегата гарантирует согласованность всех дочерних объектов.

### Value Objects (Объекты-значения)

**Расположение:** `domain/value_objects/`

Неизменяемые (immutable) доменные примитивы, определяемые своим значением, а не идентичностью. Используются для типобезопасного представления доменных концепций: идентификаторов, хешей, временных меток и других атомарных значений.

### Entities (Сущности)

**Расположение:** `domain/entities/`

Доменные сущности, организованные по провайдерам. Каждый провайдер (ChEMBL, PubChem, UniProt и др.) имеет собственный набор сущностей, описывающих структуру данных конкретного источника.

### Schemas (Схемы)

**Расположение:** `domain/schemas/`

Схемы валидации на основе **Pandera** `DataFrameModel`. Определяют структуру, типы и ограничения для DataFrame на каждом уровне медальонной архитектуры (Silver, Gold). Обеспечивают автоматическую проверку данных при трансформации.

## Дополнительные компоненты домена

### Фильтрация

**Расположение:** `domain/filtering/`

Правила фильтрации данных, экстернализированные в YAML-конфигурации (см. ADR-028). Позволяют декларативно определять условия отбора записей без изменения кода.

### Нормализация

**Расположение:** `domain/normalization/`

Модули нормализации данных:
- `normalization_dates.py` — приведение дат к каноническому формату
- `normalization_authors.py` — нормализация имён авторов
- `normalization_pages.py` — нормализация номеров страниц
- `normalization_chembl.py` — специфичная нормализация данных ChEMBL

### Классификация ошибок

**Расположение:** `domain/error_classifier.py`, `domain/error_types.py`

Классификация ошибок по категориям:
- **Critical** — критические ошибки, требующие остановки пайплайна
- **Recoverable** — восстановимые ошибки, допускающие повторную попытку
- **DQ (Data Quality)** — ошибки качества данных, направляемые в карантин

### Исключения

**Расположение:** `domain/exceptions/`

Иерархия доменных исключений, структурированная по типам: критические, восстановимые, связанные с качеством данных.

## Структура директории domain

```
domain/
├── ports/              # Protocol-интерфейсы
├── aggregates/         # DDD-агрегаты
├── value_objects/      # Неизменяемые примитивы
├── entities/           # Сущности по провайдерам
├── schemas/            # Pandera-схемы валидации
├── filtering/          # Правила фильтрации
├── normalization/      # Модули нормализации
├── exceptions/         # Доменные исключения
├── contracts/          # DQ-контракты
├── control_plane/      # Манифесты и реестры запусков
├── config/             # Доменная конфигурация
├── models/             # Доменные модели
├── validation/         # Логика валидации
├── error_classifier.py # Классификатор ошибок
├── error_types.py      # Типы ошибок
├── context.py          # Контекст выполнения
└── medallion.py        # Константы медальонной архитектуры
```
