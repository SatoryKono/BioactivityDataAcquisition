# Провайдеры данных

BioETL поддерживает 8 провайдеров — источников биологических и библиографических данных. Каждый провайдер реализован как отдельный адаптер в инфраструктурном слое с собственными настройками rate limiting (ограничения частоты запросов) и устойчивости.

| Провайдер | Типы сущностей | Статус | Rate Limit |
|-----------|---------------|--------|------------|
| **ChEMBL** | Activity, Assay, Molecule, Target, Target Component, Protein Class, Cell Line, Compound Record, Publication, Publication Term/Similarity, Subcellular Fraction, Tissue | Production | 3 req/sec |
| **PubChem** | Compound | Production | 5 req/sec |
| **UniProt** | Protein | Production | 10 req/sec (100 req/sec с API key) |
| **UniProt ID Mapping** | ID Mapping | Production | Локальная задача / без внешнего ограничения |
| **PubMed** | Publication | Production | 3 req/sec (10 req/sec с API key) |
| **CrossRef** | Publication | Production | Polite pool |
| **OpenAlex** | Publication | Production | ~10 req/sec |
| **Semantic Scholar** | Publication | Production | 0.1 req/sec (1 req/sec с API key) |

## Описание провайдеров

### ChEMBL

[ChEMBL](https://www.ebi.ac.uk/chembl/) — крупнейшая открытая база данных биоактивности, поддерживаемая EMBL-EBI. Содержит данные о биоактивности молекул, мишенях, анализах и связанных публикациях.

BioETL поддерживает 12 типов сущностей ChEMBL — это наиболее полный провайдер в системе. Используется пагинированный доступ через REST API с ограничением 3 запроса в секунду.

### PubChem

[PubChem](https://pubchem.ncbi.nlm.nih.gov/) — база данных химических соединений и биоактивности от NCBI (National Center for Biotechnology Information). BioETL извлекает данные о соединениях (Compound) через PUG REST API.

### UniProt

[UniProt](https://www.uniprot.org/) — комплексный ресурс информации о последовательностях и функциях белков. BioETL извлекает данные о белках (Protein) через REST API. При наличии API-ключа доступен повышенный лимит — 100 запросов в секунду.

### UniProt ID Mapping

Сервис маппинга идентификаторов UniProt — позволяет преобразовывать идентификаторы между различными базами данных (например, UniProt → PDB, UniProt → ChEMBL). Работает как локальная задача без ограничений на внешние запросы.

### PubMed

[PubMed](https://pubmed.ncbi.nlm.nih.gov/) — база данных биомедицинских публикаций от NCBI. BioETL извлекает метаданные публикаций через E-utilities API. Для работы рекомендуется указать email (`BIOETL_PUBMED_EMAIL`) и API-ключ (`BIOETL_PUBMED_API_KEY`) для повышенных лимитов.

### CrossRef

[CrossRef](https://www.crossref.org/) — реестр DOI и метаданных научных публикаций. BioETL использует Polite pool — режим работы с повышенным приоритетом при указании контактного email (`BIOETL_CROSSREF_EMAIL`).

### OpenAlex

[OpenAlex](https://openalex.org/) — открытый каталог научных работ, авторов, организаций и источников. Является преемником Microsoft Academic Graph. BioETL извлекает метаданные публикаций с ограничением около 10 запросов в секунду. Для Polite pool рекомендуется указать email (`BIOETL_OPENALEX_EMAIL`).

### Semantic Scholar

[Semantic Scholar](https://www.semanticscholar.org/) — платформа для поиска научной литературы на основе AI от Allen Institute for AI. BioETL использует Academic Graph API. Без API-ключа доступен только 1 запрос в 10 секунд; с ключом (`BIOETL_SEMANTICSCHOLAR_API_KEY`) — 1 запрос в секунду.

## Общие механизмы устойчивости

Все провайдеры используют унифицированный HTTP-клиент (см. ADR-032) с общими механизмами:

- **Rate Limiting** — ограничение частоты запросов, индивидуальное для каждого провайдера
- **Circuit Breaker** — автоматическое размыкание при серии ошибок (по умолчанию: 5 ошибок подряд, восстановление через 300 секунд)
- **Exponential Backoff** — экспоненциальная задержка при повторных попытках
- **Карантин** (Dead-Letter Queue) — записи, не прошедшие валидацию, направляются в карантинное хранилище
