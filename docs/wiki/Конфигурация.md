# Конфигурация

BioETL использует многоуровневую систему конфигурации: переменные окружения, YAML-файлы и профили нормализации.

---

## Переменные окружения

Все переменные следуют паттерну `BIOETL_{ГРУППА}_{ПАРАМЕТР}`. Для локальной разработки значения по умолчанию обычно достаточны.

### Core (основные)

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `BIOETL_ENV` | Среда выполнения (`dev` / `staging` / `prod`) | `dev` |
| `BIOETL_DATA_DIR` | Базовая директория для данных Bronze/Silver/Gold | `data` |
| `BIOETL_DEBUG` | Включить отладочные функции | `false` |
| `BIOETL_TEST_MODE` | Использовать фикстуры вместо реальных API | `false` |

### Pipeline (пайплайн)

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `BIOETL_PIPELINE__BATCH_SIZE` | Записей в батче (1–10000) | `100` |
| `BIOETL_PIPELINE__CHECKPOINT_INTERVAL` | Интервал сохранения чекпоинта (≥100 записей) | `1000` |
| `BIOETL_PIPELINE__MAX_CONCURRENT_BATCHES` | Максимум параллельных батчей (1–16) | `4` |
| `BIOETL_PIPELINE__HEARTBEAT_INTERVAL` | Интервал heartbeat блокировки (5–60 сек) | `30` |

### Provider API Keys (API-ключи провайдеров)

| Переменная | Описание |
|------------|----------|
| `BIOETL_UNIPROT_API_KEY` | API-ключ UniProt (повышенные лимиты) |
| `BIOETL_PUBMED_API_KEY` | API-ключ NCBI E-utilities |
| `BIOETL_PUBMED_EMAIL` | Email для идентификации в NCBI |
| `BIOETL_OPENALEX_EMAIL` | Email для Polite pool OpenAlex |
| `BIOETL_SEMANTICSCHOLAR_API_KEY` | API-ключ Semantic Scholar |
| `BIOETL_CROSSREF_EMAIL` | Email для Polite pool Crossref |

### Security (безопасность)

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `BIOETL_PII_SALT_CURRENT` | Соль для хеширования PII (≥32 символа, обязательно в prod) | — |
| `BIOETL_PII_SALT_NEXT` | Следующая соль для ротации | — |
| `BIOETL_SALT_ROTATION_ACTIVE` | Активна ли ротация соли | `false` |

### Observability (наблюдаемость)

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `BIOETL_LOG_LEVEL` | Уровень логирования (`DEBUG`/`INFO`/`WARNING`/`ERROR`/`CRITICAL`) | `INFO` |
| `BIOETL_LOG_FORMAT` | Формат логов (`json` / `text`) | `json` |
| `BIOETL_LOG_FILE` | Путь к файлу логов | `reports/logs/bioetl.log` |
| `BIOETL_METRICS_ENABLED` | Включить метрики Prometheus | `true` |
| `BIOETL_METRICS_PORT` | Порт HTTP-сервера Prometheus | `8000` |
| `BIOETL_OBSERVABILITY__TRACING_ENABLED` | Включить трассировку OpenTelemetry | `false` |
| `BIOETL_OBSERVABILITY__DQ_MONITOR_ENABLED` | Включить мониторинг качества данных | `false` |

### Data Quality (качество данных)

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `BIOETL_DQ_SOFT_THRESHOLD` | Порог предупреждения (доля ошибок) | `0.05` |
| `BIOETL_DQ_HARD_THRESHOLD` | Порог отказа батча (доля ошибок) | `0.20` |

### Resilience (устойчивость)

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `BIOETL_CB_FAILURE_THRESHOLD` | Ошибок подряд для размыкания Circuit Breaker | `5` |
| `BIOETL_CB_RECOVERY_TIMEOUT` | Таймаут восстановления Circuit Breaker (секунды) | `300` |
| `BIOETL_RETRY_MAX_ATTEMPTS` | Максимум повторных попыток | `3` |
| `BIOETL_RETRY_MULTIPLIER` | Множитель экспоненциального backoff | `2.0` |

### Delta Lake

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `BIOETL_DELTA_VACUUM_RETENTION` | Удержание VACUUM (дни) | `7` |
| `BIOETL_DELTA_FORENSIC_RETENTION` | Удержание для forensic-анализа (дни) | `7` |

### Quarantine (карантин)

| Переменная | Описание | По умолчанию |
|------------|----------|-------------|
| `BIOETL_QUARANTINE_RETENTION_DAYS` | Срок хранения карантинных записей (дни) | `30` |
| `BIOETL_QUARANTINE_PAYLOAD_MAX_SIZE` | Максимальный размер payload (байты) | `65536` |

## YAML-конфигурации

Конфигурационные файлы расположены в директории `configs/`:

```
configs/
├── base/          # Базовые конфигурации
├── entities/      # Конфигурации сущностей по провайдерам
├── composites/    # Конфигурации композитных пайплайнов
├── contracts/     # DQ-контракты
├── quality/       # Правила качества данных
├── providers/     # Настройки провайдеров
├── enums/         # Экстернализированные enum-значения
├── vocab/         # Словари и справочники
├── workflows/     # Конфигурации рабочих потоков
└── _schema/       # JSON Schema для валидации конфигураций
```

### Конфигурации сущностей

Каждая сущность описывается в YAML-файле в формате Unified Entity Config (см. ADR-039). Файл объединяет конфигурацию пайплайна, схемы данных и правила качества в едином месте.

### DQ-контракты

Контракты качества данных (`configs/contracts/`) определяют пороговые значения и правила проверки для каждого типа сущности на уровне Gold.

## Профили нормализации

Нормализация данных при трансформации из Bronze в Silver управляется профилями, определёнными в доменном слое:

- **Даты** — приведение к каноническому формату ISO 8601
- **Авторы** — нормализация имён авторов публикаций
- **Страницы** — нормализация номеров страниц
- **ChEMBL-специфичная** — нормализация данных ChEMBL

## Файл `.env`

Для настройки локального окружения скопируйте шаблон:

```bash
cp .env.example .env
```

Полный список переменных с комментариями — в файле [`.env.example`](https://github.com/SatoryKono/BioactivityDataAcquisition/blob/main/.env.example).
