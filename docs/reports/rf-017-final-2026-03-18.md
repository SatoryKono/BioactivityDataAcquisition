# RF-017 Final Plan (Revised)

Date: 2026-03-18

## RF-017: Constructor Pressure Burn-down

Цель RF-017: снизить constructor pressure там, где он уже мешает понятности dependency graph, применив bundle/context только там, где это подтверждено архитектурным паттерном. Отказаться от `**kwargs` для сохранения строгой типизации (`mypy --strict`) и внедрить систему контролируемых исключений (waivers) для CI, чтобы out-of-scope классы не блокировали разработку.

## 2. CI Policy: Внедрение Waiver-механизма (Pre-requisite)

Прежде чем менять код, необходимо адаптировать `src/tools/scripts/check_constructor_args.py`. 
Глобальный gate будет валиться на 3-й группе, если мы просто оставим их как есть.

**Действия:**
1. Создать файл `.github/linters/constructor_waivers.yaml`.
2. Обновить `check_constructor_args.py`, чтобы он читал этот файл.
3. Формат waiver-а: класс, разрешенное количество аргументов, причина, владелец, expiry_date.
4. Максимальный срок жизни (TTL) waiver-а — не более 6 месяцев (обязательный пересмотр). Если срок истек, CI падает.

*Definition of Done:* Скрипт пропускает легаси-классы из группы 2, если они описаны в yaml-файле и срок не истек.

## 3. Deprecation Protocol и Строгая Типизация (`BaseTransformer`)

Никаких `**kwargs`. Чтобы пройти миграцию гладко и не сломать типизацию (`mypy --strict`), используется следующий протокол:

**Шаг 1: Расширение сигнатуры явными `legacy_` аргументами.**
На время миграции (Волна 1) `BaseTransformer` получает временный Waiver в CI. Waiver живет строго до завершения Wave 1 и удаляется в финальном PR RF-017.
Сигнатура становится гибридной, но *строго типизированной*:
```python
def __init__(
    self,
    provider: str,
    entity_type: str | None = None,
    silver_filters: SilverFilterConfig | None = None,
    gold_filters: GoldFilterConfig | None = None,
    dependencies: TransformerDependencyContext | None = None,
    *,
    # --- Legacy Transitional Args (To be removed at the end of RF-017) ---
    legacy_tracer: TracingPort | None = None,
    legacy_metrics: MetricsPort | None = None,
    legacy_identity_service: IdentityService | None = None,
    legacy_pii_hasher: PiiHasherPort | None = None,
    legacy_data_normalizer: DataNormalizationPort | None = None,
    legacy_contract_policy: ContractPolicyPort | None = None,
) -> None:
```
Внутри конструктора: если `dependencies` равен `None`, собираем его из `legacy_` аргументов и выдаем `warnings.warn("... deprecated ...", DeprecationWarning, stacklevel=2)`.

**Шаг 2: Порядок миграции callsites.**
Строгая последовательность изменений (снизу вверх по графу вызовов):
1. **Composition**: Обновить фабрики, чтобы они собирали `TransformerDependencyContext`.
2. **Unit Tests**: Обновить моки и фикстуры тестов, чтобы они передавали `dependencies`.
3. **Provider Transformers**: Обновить сигнатуры всех дочерних трансформеров, чтобы они принимали `dependencies` и пробрасывали в `super().__init__`.

**Шаг 3: Удаление легаси (Post-migration contract).**
Как только все callsites обновлены (warnings в логах CI исчезли), `legacy_` аргументы физически удаляются из `BaseTransformer`. Waiver для `BaseTransformer` удаляется из `constructor_waivers.yaml`. 
Итоговый конструктор содержит ровно 5 аргументов.

## 4. Guardrails для `TransformerDependencyContext`

Критический риск — превращение `TransformerDependencyContext` в Service Locator. Вводятся жесткие архитектурные правила:

1. **Только Shared Collaborators:** В контекст могут входить *только* технические порты, общие для 100% трансформеров (`tracer`, `metrics`, `identity_service`, `pii_hasher`, `data_normalizer`, `contract_policy`).
2. **No Provider-Specific Services:** Запрещено добавлять в контекст специфичные экстракторы (например, `AuthorExtractor` из PubMed). Они передаются как отдельные строго типизированные аргументы в конструктор конкретного `PubMedPublicationTransformer`.
3. **No Scalar Configs:** Запрещено добавлять в бандл скалярные значения конфигурации (например, `provider`, `entity_type`). Они остаются явными аргументами.
4. **Enforced Whitelist:** Правило автоматизируется через архитектурный тест (`tests/architecture/test_transformer_context_fields.py`), который жестко фиксирует whitelist допустимых полей в `TransformerDependencyContext`. Любое расширение бандла сломает билд и потребует явного изменения теста после архитектурного ревью.

## 5. Локальная обработка `JoinPlannerService` и `BatchProcessingService`

**`BatchProcessingService`:**
Использовать уже существующую в фабриках (Composition) абстракцию `BatchProcessingComponents` (содержит `transformer`, `writer`, `batch_metrics`). 
Удалить избыточный аргумент `logger` (он уже доступен через `context.logger`). 
*Итог: снижение с 9 до 6 аргументов без создания "мусорных" бандлов.*

**`JoinPlannerService`:**
Объединить логически связанную фазу подготовки (`deduplicator`, `aggregator`, `renamer`, `conflict_resolver`) в локальный иммутабельный dataclass `JoinPreparationCollaborators`. 
*Итог: снижение с 10 до 7 аргументов.*

## 6. Verify strategy (Quality Gates)

На каждую волну и ПР запускаются следующие Quality Gates:

1. **Static Analysis:**
   ```bash
   uv run mypy --strict --no-incremental src/bioetl/
   ```
   *Критерий:* Отсутствие ошибок, `**kwargs` не используются для маскировки типов.

2. **AST Constructor Gate:**
   ```bash
   uv run python src/tools/scripts/check_constructor_args.py
   ```
   *Критерий:* Скрипт зеленый. Срабатывают только утвержденные waiver-ы из `constructor_waivers.yaml`.

3. **Transformer Unit Tests:**
   ```bash
   uv run pytest tests/unit/application/pipelines/ -W error::DeprecationWarning
   ```
   *Критерий:* Тесты проходят без выброса DeprecationWarning (гарантия, что все тесты переведены на новый API).

4. **Architecture Tests:**
   ```bash
   uv run pytest tests/architecture/ -q
   ```

## 7. Критерии закрытия RF-017 (Definition of Done)

RF-017 считается завершённым, если:
1. Матрица миграции (Раздел 1) выполнена на 100%. Целевые метрики аргументов достигнуты (диапазон 5–7 для мигрированных классов).
2. Внедрен и работает механизм `.github/linters/constructor_waivers.yaml` для остаточного легаси.
3. Из `BaseTransformer` полностью удалены `legacy_` аргументы, `**kwargs` не используется.
4. Выполнены все Quality Gates (`mypy --strict`, отсутствие DeprecationWarnings в логах тестов).
5. Архитектурные правила для `TransformerDependencyContext` соблюдены (внедрен архитектурный тест-guardrail на whitelist полей).
