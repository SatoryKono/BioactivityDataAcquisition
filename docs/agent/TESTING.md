# Навыки Тестирования BioETL

Этот документ описывает стратегию и инструменты тестирования.

## 1. Цели и Метрики
*   **Покрытие:** Цель > 95% line coverage. Приоритет: Domain > Application > Infrastructure.
*   **Время выполнения:** < 5 минут для unit-тестов.
*   **Инструменты:** `pytest`, `pytest-asyncio`, `pytest-cov`, `hypothesis`.

## 2. Уровни тестирования
1.  **Unit (Модульные):** `tests/unit/`
    *   Изолированная проверка классов/функций.
    *   **Правило:** Не мокать доменные сущности (Value Objects, Entities) — используйте реальные объекты.
    *   Мокайте инфраструктуру (порты/адаптеры).
2.  **Integration (Интеграционные):** `tests/integration/`
    *   Проверка взаимодействия с внешними системами (в Docker или с моками высокого уровня).
    *   HTTP: Используйте `vcr.py` или `respx` для записи/воспроизведения ответов API. Кассеты должны быть очищены от секретов.
3.  **E2E (End-to-End):** `tests/e2e/`
    *   Маркер `@pytest.mark.e2e`.
    *   Проверка полного цикла пайплайна с in-memory инфраструктурой.

## 3. Особенности реализации
*   **Асинхронные тесты:** Используйте плагин `pytest-asyncio`.
*   **Mocking:**
    *   Для синхронного кода в `run_in_executor`: используйте `Mock` (не `AsyncMock`), чтобы избежать ошибок возврата корутины.
    *   Для `PipelineServices`: явно мокайте `logger.bind`.
*   **Property-Based Testing:** Используйте `hypothesis` для генерации граничных случаев данных.

## 4. Тестирование Архитектуры
*   Файл `tests/test_architecture.py` проверяет соблюдение слоев (imports), наличие docstrings и стандарты именования.
*   Запуск этого теста обязателен перед коммитом (часть CI).

## 5. Локальный запуск
*   Используйте `Makefile`:
    *   `make test` — запуск всех тестов.
    *   `make unit` — только модульные.
    *   `make lint` — проверка стиля.
*   Запускайте через модуль: `python -m pytest` (для корректного `sys.path`).
