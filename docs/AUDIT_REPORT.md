# Аудит документации BioETL

**Дата:** 2025-12-15
**Статус:** Черновик

## 1. Резюме (Executive Summary)

В ходе аудита документации выявлены существенные структурные и содержательные несоответствия правилам проекта (`RULES.md` v5.0):
1.  **Избыточное дублирование:** Файл `RULES.md` в корне и файлы в `docs/00-project_rules/` содержат практически идентичную информацию, что создает путаницу и усложняет поддержку.
2.  **Нарушение языковых требований:** Значительная часть технической документации в `docs/01-architecture/` и некоторые файлы в `docs/00-project_rules/` написаны на английском языке, в то время как правилами предписан русский язык.
3.  **Отсутствующие артефакты:** Не найдены директории и файлы, на которые ссылаются правила (`docs/contracts/gold/`, `docs/runbooks/`).
4.  **Тяжеловесность `RULES.md`:** Корневой файл правил нарушает принцип "Краткого справочника", являясь полным техническим мануалом (версия 5.0).

---

## 2. Структурный анализ (Structure Analysis)

### 2.1. Конфликт `RULES.md` и `docs/00-project_rules/`
Текущая ситуация:
*   **`RULES.md` (Root):** Содержит полную версию правил v5.0 (Архитектура, Medallion, Operations, DR, Code Style и т.д.).
*   **`docs/00-project_rules/01-project-rules.md`:** Содержит почти полную копию `RULES.md` (также помечена как v5.0).
*   **`docs/00-project_rules/02-user-rules.md`:** Дублирует правила разработки, проверки PR и ограничения (MUST/MUST NOT), частично перекрывая `01-project-rules.md`.

**Проблема:** При изменении правил придется править 3 файла одновременно.
**Рекомендация:**
1.  Превратить `RULES.md` в навигационный файл (Index), содержащий только ссылки на разделы в `docs/`.
2.  Объединить содержимое `01-project-rules.md` и `02-user-rules.md` в логические разделы внутри `docs/` (например, `docs/standards/`, `docs/governance/`).

### 2.2. Нарушение принципа "Краткого справочника"
В `RULES.md` (и его дубликатах) содержатся глубокие технические детали, которые должны быть вынесены в специализированные разделы:
*   Подробности конфигурации `delta-rs` и `VACUUM`.
*   Спецификации схемы JSON логов.
*   Детальные сценарии DR Runbooks.
*   Примеры кода для Backfill Lock.
