## Типы поверхностей документации

Используйте документацию репозитория со следующим приоритетом:

- **Канонические активные документы**: `docs/00-05`. Эти страницы определяют
  текущие правила, архитектуру, руководства, эксплуатацию и справочные
  контракты проекта.
- **Только репозиторий / расширенные рабочие документы**: планирование,
  курируемые свидетельства, инструкции для AI-агентов и другие расширенные
  рабочие материалы могут существовать вне опубликованной поверхности MkDocs.
  Они остаются доступными через ссылки на пути в репозитории, но не
  переопределяют канонические активные документы.
- **Архивные документы**: `docs/99-archive/`. Только исторический контекст.

Полезные точки входа для ненормативных поверхностей:

- Путь репозитория `docs/plans/README.md` — индексированные сохранённые
  артефакты планирования (рабочая поверхность только в репозитории, не
  публикуется в MkDocs)
- Путь репозитория `docs/reports/index.md` — курируемые свидетельства и
  ограниченные внутренние отчёты только в репозитории
- [Политика файлов](../../00-project/governance/03-file-policy.md) — гигиена структуры,
  границы хранения и топология sidecar-файлов
- Путь репозитория `reports/README.md` — сгенерированные или рабочие выходы
  анализа до курирования
- Путь репозитория `docs/00-project/ai/README.md` — карта документации AI
  верхнего уровня для агентов, памяти, промптов и навыков
- Путь репозитория `.codex/agents/ORCHESTRATION.md` — Codex как источник
  истины оркестрации
- Путь репозитория `docs/00-project/ai/agents/README.md` — опубликованное
  зеркало агентов и руководства по среде исполнения
- Путь репозитория `docs/00-project/ai/skills/README.md` — зеркало навыков
  и индексы
- [Индекс архива эксплуатации](../../05-operations/archive-index.md) —
  опубликованная архивная линия для исторических эксплуатационных
  свидетельств и вспомогательных заметок по развёртыванию

## Миссия проекта

Создать надёжный, масштабируемый и сопровождаемый конвейер данных для
получения и обработки данных о биоактивности из различных публичных
источников в единый, готовый к анализу формат.

## Поддерживаемые локальные рабочие процессы

В настоящее время репозиторий поддерживает три практических режима локального
исполнения:

- **CI / клонирование на одной ОС**: используйте `uv run python -m ...` и
  поддерживаемые Make-цели, такие как `make install`, `make test`,
  `make lint`.
- **Windows PowerShell в смешанной установке Windows + WSL**: инициализация
  через `.\scripts\engineering\dev\setup_env_windows.ps1`, затем
  предпочтительно `.\scripts\engineering\dev\run_pytest.ps1`,
  `.\scripts\engineering\dev\run_mypy.ps1` или
  `.\.venv-win\Scripts\python.exe -m ...`.
- **WSL/Linux в смешанной установке Windows + WSL**: инициализация через
  `bash scripts/engineering/dev/setup_env_wsl.sh`, затем предпочтительно
  `bash scripts/engineering/dev/run_pytest.sh`,
  `bash scripts/engineering/dev/run_mypy.sh` или
  `"${BIOETL_WSL_VENV_DIR:-$HOME/.venvs/bioetl}/bin/python" -m ...`.

Не используйте один и тот же `.venv` совместно в PowerShell и WSL.
Поддерживаемый путь смешанной установки использует `.venv-win` в PowerShell и
внешний WSL-venv по адресу `${BIOETL_WSL_VENV_DIR:-$HOME/.venvs/bioetl}` по
умолчанию.

### Композитный конвейер (ADR-026)

BioETL поддерживает обогащение данных из нескольких источников через
композитные конвейеры:

```bash
# Запуск композитного конвейера публикаций (seed из ChEMBL, обогащение из CrossRef, OpenAlex, PubMed)
bioetl run-composite --composite publication --seed-limit 1000
```

См. [диаграмму композитного конвейера](../../02-architecture/diagrams/foundation/29-composite-pipeline-workflow.mmd) для визуализации рабочего процесса.

## Начало работы

```bash
# Клонирование и настройка
git clone <repo-url>
cd BioactivityDataAcquisition
make install

# Запуск конвейера
bioetl run --pipeline chembl_activity --limit 100

# Запуск тестов
make test
```

Сокращения для смешанной установки Windows + WSL:

```powershell
.\scripts\engineering\dev\setup_env_windows.ps1
.\scripts\engineering\dev\run_pytest.ps1 tests\ --timeout=120 -n 4 --lf
```

```bash
bash scripts/engineering/dev/setup_env_wsl.sh
bash scripts/engineering/dev/run_pytest.sh tests/ --timeout=120 -n 4 --lf
```
