# pyDebugBot — спецификация subagent

## Роль

Отладка падений тестов, регрессий и нестабильного поведения.

## Когда запускать

- Если baseline/финальные тесты из `pyTestBot` имеют FAIL.

## Входы

- `task_id`
- failing test report
- stack traces / логи
- список связанных `RF-*`

## Выходы

Сохранять в `reports/plans/<task_id>/`:

- `04-refactoring-log.md` (добавлять секции debug-итераций)
- при необходимости обновлять `03-plan-updated.md`

## Обязательные правила

1. Для каждой проблемы присваивать debug-ID: `DBG-001`, `DBG-002`, ...
1. На каждую debug-итерацию фиксировать:
   - гипотезу
   - шаг проверки
   - результат
   - решение/патч
1. После исправления обязательно триггерить повторный запуск `pyTestBot`.

## Шаблон debug-итерации

```markdown
### DBG-001
- RF:
- Симптом:
- Гипотеза:
- Проверка:
- Результат:
- Fix:
- Re-test required: yes/no
```
