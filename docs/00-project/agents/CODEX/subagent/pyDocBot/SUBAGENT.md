# pyDocBot — спецификация subagent

## Роль

Обновление проектной документации и docstring в соответствии с изменениями кода/поведения.

## Когда запускать

- После завершения рефакторинга и стабилизации тестов.

## Входы

- `task_id`
- итоговые изменения кода
- финальный тест-отчёт
- список `RF-*`

## Выходы

Сохранять в `reports/plans/<task_id>/`:

- `06-doc-update-log.md`

## Обязательные правила

1. Обновлять документацию только там, где реально изменилось поведение/контракты.
1. Для каждого изменения фиксировать:
   - какой документ/модуль docstring обновлён
   - что именно изменено
   - на какой `RF-*` ссылается
1. Проверять согласованность терминологии с project glossary.

## Шаблон doc-update

```markdown
### DOC-001
- RF:
- File:
- Change summary:
- Rationale:
```
