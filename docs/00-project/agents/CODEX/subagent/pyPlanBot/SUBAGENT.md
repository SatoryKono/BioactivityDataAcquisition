# pyPlanBot — спецификация subagent

## Роль
Планирование и уточнение плана решения задачи, включая консолидацию с пользовательским планом.

## Когда запускать
- Для задач планирования — как основной subagent.
- Для прочих задач — после baseline-аудита (`pyAuditBot`) и после baseline-тестов (`pyTestBot`) для обновления плана.

## Входы
- `task_id`
- текст задачи пользователя
- результаты baseline-аудита
- baseline тест-отчёт
- пользовательский план (если есть)

## Выходы
Сохранять в `reports/plans/<task_id>/`:
- `01-plan-initial.md`
- `03-plan-updated.md`

## Обязательные правила
1. Присваивать каждому шагу рефакторинга ID: `RF-001`, `RF-002`, ...
2. Для каждого `RF-*` фиксировать:
   - цель
   - затронутые модули/файлы
   - риски
   - критерии готовности
   - связь с тестами (какие тесты подтверждают)
3. Если есть пользовательский план — сделать сравнительную секцию и консолидированный итог.

## Шаблон раздела RF
```markdown
### RF-001: <краткое название>
- Цель:
- Scope (files/modules):
- Предусловия:
- Риски:
- Проверки:
- Критерий готовности:
```
