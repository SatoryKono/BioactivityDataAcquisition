# MUSE.md: Context & Instructions for BioETL (Muse Code)

*Статус: internal-published (Internal / Extended)*

## 0. Canonical runtime entry

Read first, in this order:

1. `AGENTS.md`
1. `.codex/agents/CODEX-RUNTIME.md` and `.junie/agents/JUNIE-RUNTIME.md` (equal peers; plus `.junie/guidelines.md`)
1. `docs/00-project/NORMATIVE_SOURCES.md`

This guide is a navigation mirror. It does not override those contracts and
does not define new runtime behavior (see `policy/AI_RUNTIME_MIRROR_OWNERSHIP.md`).
There is no tracked `.muse/agents/**` or `.muse/skills/**` tree on `main`;
Muse sessions reuse the Codex canonical sources below.

## 1. Session guardrails

- **Response language:** by default answer in Russian when the user writes in
  Russian. GitHub review bodies and inline comments via `gh pr review` (or an
  equivalent API) MUST be written in Russian. Keep code, commands, paths,
  identifiers, and API field names in their original form.
- **Technical debt:** increasing debt budgets is FORBIDDEN
  (scorecards, exemptions, hotspot thresholds and family caps).
- **Local-only default:** do not introduce Docker, Redis, or external
  orchestration unless the task explicitly requires it (ADR-010).
- **Env files:** any `.env` / `.env.*` file is secret-bearing and
  machine-local. Do NOT create, edit, rename, move, overwrite, or delete it
  without explicit per-task user approval. Reading is permitted.
- **Secrets:** never commit credentials to tracked YAML, docs, tests, or logs.
  MCP settings carry secret *names* only; values are supplied by the user.
- **Task classes:** follow the `AGENTS.md` context-tier table (hash-only
  rebind skips RULES/ADR with `BIOETL_AI_MEMORY_MODE=off`; V2 loads one
  matching role/skill; V3/V4 keep the full package with `pre-task`).

## 2. Skills

`.codex/skills/` is the canonical project skill source (14 skills, see
`.codex/skills/SKILLS-CATALOG.md`). Do NOT duplicate them under
`.agents/skills/` — that directory is the reserved SSOT slot for
Muse-native project skills and stays empty until a reviewed change populates
it. Verified in this session: `muse skills import --from codex --dry-run`
resolves only user-level `~/.codex/skills` (currently empty), so project
skills are wired per-skill at user level:

```bash
muse skills install <repo>/.codex/skills/py-doc-bot --scope user
muse skills list --source all --trust-workspace --json
```

Install only the skills matching the task (e.g. `py-doc-bot` for docs,
`py-debug-bot` for read-only diagnosis). External `skills-lock.json` skills
(CodeRabbit/Qodo) are opt-in and not part of the base setup.

## 3. MCP

Portable workspace entrypoint: `.mcp.json` (generated by
`scripts/ai/codex/setup_mcp.py`; wrappers in `scripts/ai/mcp/*_wrapper.sh`).
Machine-local Codex projections (`~/.codex/config.toml` managed MCP block,
`.codex/settings.json`) are evidence only — never copy values blindly.

Muse user-level file: `${XDG_CONFIG_HOME:-$HOME/.config}/muse/settings.json`,
key `mcpServers` (camelCase). Every server gets `"mode": "optional"` so one
failing server cannot block Muse startup. Base set (stdio, run Muse from the
repo root or replace `args` with absolute paths):

```json
"mcpServers": {
  "memory":     { "type": "stdio", "command": "bash", "args": ["scripts/ai/mcp/mcp_memory_wrapper.sh"], "env": { "NPM_CONFIG_CACHE": ".cache/npm-cache", "MEMORY_FILE_PATH": "docs/00-project/ai/memory/mcp-memory.json" }, "startup_timeout_sec": 120, "mode": "optional" },
  "filesystem": { "type": "stdio", "command": "bash", "args": ["scripts/ai/mcp/mcp_filesystem_wrapper.sh"], "env": { "NPM_CONFIG_CACHE": ".cache/npm-cache" }, "mode": "optional" },
  "fetch":      { "type": "stdio", "command": "bash", "args": ["scripts/ai/mcp/mcp_fetch_wrapper.sh"], "env": { "UV_CACHE_DIR": ".cache/uv-cache", "UV_TOOL_DIR": ".cache/uv-tools", "NPM_CONFIG_CACHE": ".cache/npm-cache" }, "startup_timeout_sec": 300, "mode": "optional" },
  "github":     { "type": "stdio", "command": "bash", "args": ["scripts/ai/mcp/github-mcp-wrapper.sh"], "env": { "GITHUB_TOOLSETS": "context,issues,pull_requests,repos,users,actions,code_security,dependabot,notifications", "GITHUB_EXCLUDE_TOOLS": "create_or_update_file,push_files,delete_file,fork_repository,create_repository,merge_pull_request,actions_run_trigger", "GITHUB_LOCKDOWN_MODE": "true" }, "startup_timeout_sec": 180, "mode": "optional" },
  "context7":   { "type": "stdio", "command": "bash", "args": ["scripts/ai/mcp/mcp_context7_wrapper.sh"], "startup_timeout_sec": 240, "mode": "optional" },
  "ast-grep":   { "type": "stdio", "command": "bash", "args": ["scripts/ai/mcp/mcp_ast_grep_wrapper.sh"], "startup_timeout_sec": 120, "mode": "optional" }
}
```

Extension servers (`brave-search`, `deepwiki`, `ref`, `mermaid`,
`adr-analysis`, `code-analyzer`, `prometheus`, `grafana`, `neo4j-*`,
`docker`, `mutmut`, `code-interpreter`, `github-actions`) follow the same
shape — see `.mcp.json`. The tracked file is generated Muse-parseable by
`scripts/ai/codex/setup_mcp.py`: every entry carries `"mode": "optional"`
so one failing server cannot disable all of MCP, and remote entries use
`"type": "streamable-http"`. Remote servers needing keys (`DEEPWIKI_API_KEY`,
`REF_TOOL_API_KEY`, GitHub tokens from `.env`) are added only after the user
supplies the values; placeholders are never written. The shared-localhost
HTTP projection (ports `8813`–`8828`, `transport_mode: shared`) is an
alternative for checkouts where the MCP gateway already runs. MCP changes
apply on the next Muse launch; re-read the file after editing.

## 4. Memory

Use the canonical memory workflow, not ad-hoc notes. Repository memory
(`docs/00-project/ai/memory/*.md`) is runtime-agnostic and needs no
migration. Identify the Muse actor explicitly:

```bash
BIOETL_AI_RUNTIME=muse \
BIOETL_AI_AGENT=<active-profile-or-muse> \
python -m memory.tooling.workflow pre-task ...
python -m memory.tooling.workflow post-task ...
```

Details: `guides/MEMORY_USAGE.md`, `src/memory/DAILY_WORKFLOW.md`.
