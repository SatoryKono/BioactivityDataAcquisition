Задача: провести цикл аудита воспроизводимости пайплайна до полного устранения всех найденных проблем.

  Работай строго по шагам. Не пропускай шаги. Не завершай задачу, пока не выполнены все применимые условия.

  Обязательно используй skill `py-reproducibility-audit`.

  ==================================================
  ОБЩАЯ ЛОГИКА
  ==================================================

  Нужно выполнить два последовательных независимых аудита воспроизводимости одного и того же pipeline, затем сравнить результаты, собрать консолидированное заключение и, если найдены реальные проблемы, исправить их
  все. После исправлений цикл должен начаться заново с двух новых аудитов.

  ==================================================
  ЭТАП 1. ДВОЙНОЙ АУДИТ
  ==================================================

  1. Проведи первый аудит воспроизводимости pipeline, используя skill `py-reproducibility-audit`.
  2. Сохрани результат как `Audit A`.
  3. Затем проведи второй аудит воспроизводимости того же pipeline, также используя skill `py-reproducibility-audit`.
  4. Сохрани результат как `Audit B`.

  Требования:
  - оба аудита должны быть полноценными, а не поверхностными
  - второй аудит не должен просто копировать вывод первого
  - в каждом аудите должны быть явно указаны:
    - scope проверки
    - использованные команды
    - собранные evidence
    - найденные проблемы
    - уровень уверенности
    - вывод по воспроизводимости

  ==================================================
  ЭТАП 2. СРАВНЕНИЕ И КОНСОЛИДАЦИЯ
  ==================================================

  1. Сравни `Audit A` и `Audit B`.
  2. Выдели:
     - совпадающие выводы
     - расхождения
     - findings с высокой уверенностью
     - findings, требующие дополнительной перепроверки
  3. Подготовь `Consolidated Audit` — единый консолидированный итог.

  В `Consolidated Audit` обязательно включи:
  - итоговый статус воспроизводимости
  - список подтверждённых проблем
  - список неподтверждённых или спорных проблем
  - root cause для каждой подтверждённой проблемы
  - список необходимых исправлений

  Не считай проблему подтверждённой, если она не подтверждается evidence или не воспроизводится повторно.

  ==================================================
  ЭТАП 3. ИСПРАВЛЕНИЕ
  ==================================================

  Выполняй Этап 3 только если `Consolidated Audit` содержит подтверждённые ошибки.

  1. Исправь все подтверждённые ошибки.
  2. Не ограничивайся частичным исправлением.
  3. Для каждого исправления зафиксируй:
     - какой defect исправлялся
     - в каких файлах внесены изменения
     - почему это root-cause fix, а не workaround
  4. После завершения исправлений обязательно снова переходи к Этапу 1:
     - проведи два новых последовательных аудита
     - снова сравни результаты
     - снова собери `Consolidated Audit`

  ==================================================
  ЭТАП 4. УСЛОВИЕ ЗАВЕРШЕНИЯ
  ==================================================

  Если `Consolidated Audit` показывает, что ошибок больше нет:
  - завершай задачу

  Если ошибки всё ещё есть:
  - не завершай задачу
  - возвращайся к Этапу 3 и продолжай цикл

  ==================================================
  ФОРМАТ ОТЧЁТА
  ==================================================

  На каждом цикле выводи отчёт в следующей структуре:

  ## Audit A
  - scope
  - commands
  - findings
  - conclusion

  ## Audit B
  - scope
  - commands
  - findings
  - conclusion

  ## Consolidated Audit
  - confirmed findings
  - disputed findings
  - root causes
  - final reproducibility verdict

  ## Fixes Applied
  - file
  - change
  - defect addressed

  ## Re-Verification Verdict
  - `Errors Found`
  - `Errors Fixed`
  - `No Errors`

  ==================================================
  ДОПОЛНИТЕЛЬНЫЕ ПРАВИЛА
  ==================================================

  - не завершай задачу после одного аудита
  - не завершай задачу после одного исправления без повторного двойного аудита
  - не считай задачу выполненной, пока консолидированный аудит не подтверждает отсутствие ошибок
  - не предлагай исправления без объяснения root cause
  - не скрывай расхождения между Audit A и Audit B
  - если в среде есть ограничения, явно фиксируй их в отчёте
