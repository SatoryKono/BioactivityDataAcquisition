## Summary
Document one sanctioned public import style for composite-checkpoint governance consumers so future normalization governance changes do not drift back to internal helper-module imports.

## Problem Statement
The normalization governance generator has already been moved to the package-root checkpoint facade, but the package still exposes both the package root and `anchor_context.py` as public-ish surfaces. The latest audit did not find a runtime bug here, but it did identify a low-priority architecture clarity gap: the repo should explicitly state which import style is sanctioned for governance consumers.

## Evidence
- Governance generator now imports from the package facade in `scripts/docs/generate_pipeline_normalization_field_matrix.py`.
- Public checkpoint facade exists in `src/bioetl/application/composite/checkpoint/__init__.py`.
- Dedicated helper module remains available at `src/bioetl/application/composite/checkpoint/anchor_context.py`.
- Follow-up to the remediation implemented under the checkpoint-facade hardening work.

## Goal
Make the public import contract explicit for governance consumers and keep tests/docs aligned with that decision.

## Scope
- Decide whether governance consumers must use only `bioetl.application.composite.checkpoint` or whether `anchor_context.py` is also considered sanctioned public surface.
- Document that decision in the relevant docs/comments/tests.
- Align current governance consumers and regression guards with the chosen rule.
- Avoid broader checkpoint refactors unless necessary.

## Detailed Implementation Plan
1. Review current checkpoint package exports and governance consumers.
2. Choose the sanctioned public import style.
3. Update docs/comments/tests to describe the rule explicitly.
4. Tighten regression guards so future consumers do not silently drift away from the sanctioned style.
5. Re-run targeted tests covering checkpoint facade usage and governance generator imports.

## Acceptance Criteria
- One sanctioned public import style is explicitly documented.
- Governance consumers and their tests follow that rule.
- Future drift is prevented by at least one regression guard.

## Validation
- `rg "application\.composite\.checkpoint(\.anchor_context)?" scripts tests src`
- Targeted tests for checkpoint facade usage and governance generator imports.

## Priority
Low. This is import-style hardening, not a correctness fix.
