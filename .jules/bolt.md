## YYYY-MM-DD - [Optimize schema drift detection]
**Learning:** Polars DataFrame `to_dicts()` is used in `_compute_dq_metrics` purely to pass records for schema drift detection in `_detect_schema_drift`. The schema drift detection internally only checks `records[0]` keys for field names. Calling `.to_dicts()` on large DataFrames creates significant FFI overhead and materializes all rows in memory when only column names are needed.
**Action:** Replace `frame.to_dicts()` with a fast, lazy extraction of column names using `frame.columns` (or `records[0].keys()` if not a DataFrame), then construct a single dummy record `[{k: None for k in record_keys}]` to pass to `_detect_schema_drift`. This leverages Polars metadata instead of full materialization and dramatically improves performance for large batch schema validation.
