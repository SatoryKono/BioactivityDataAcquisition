## 2026-04-25 - [Concurrent API Rate Limiting and Dynamic Limits]
**Learning:** When implementing concurrent batch processing with limits (e.g., `asyncio.gather` for API fetches), do not truncate the input collection upfront based on the limit if the operations can yield `None` or invalid results. Enforce the limit dynamically on the successfully yielded results instead to avoid functional regressions. Furthermore, when converting sequential API batch requests to concurrent ones (e.g., for SemanticScholar), bound the concurrency and prevent external API rate limiting errors (e.g., by chunking or using an `asyncio.Semaphore`).
**Action:** Always maintain sequential limit-checking logic when refactoring for concurrency, or chunk the concurrency carefully while preserving the correct generator `yield` boundaries.
