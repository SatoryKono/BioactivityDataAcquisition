# Documentation Audit & Update Task

## Цель
Провести полный аудит документации проекта BioETL, выявить устаревшие разделы, несоответствия с кодом и обновить документацию до актуального состояния (v5.6+).

## Контекст
Проект активно развивался, были внедрены новые архитектурные решения (ADR-010 Local-Only, ADR-014 Determinism, ADR-017 Observability). Документация могла отстать от кода.

## Этапы выполнения

### 1. Аудит (Audit)
- [ ] Проверить `docs/RULES.md` на соответствие текущему коду.
- [ ] Проверить `docs/REQUIREMENTS.md` на синхронизацию с `RULES.md`.
- [ ] Проверить `docs/architecture/` на наличие устаревших диаграмм или описаний.
- [ ] Проверить `docs/providers/` на актуальность описания пайплайнов.
- [ ] Проверить `docs/contracts/` на соответствие схемам в коде.
- [ ] Выявить "мертвые" файлы документации (не ссылающиеся ниоткуда и не актуальные).

### 2. Планирование (Plan)
- [ ] Создать список необходимых изменений.
- [ ] Приоритезировать изменения (Critical > High > Medium > Low).
- [ ] Согласовать план с текущими задачами разработки.

### 3. Обновление (Update)
- [ ] Обновить `RULES.md` (версия, новые разделы).
- [ ] Обновить `REQUIREMENTS.md` (синхронизация).
- [ ] Обновить архитектурные диаграммы (если необходимо).
- [ ] Обновить документацию провайдеров.
- [ ] Обновить контракты данных.
- [ ] Удалить или архивировать устаревшие файлы.

### 4. Верификация (Verify)
- [ ] Проверить ссылки между документами.
- [ ] Проверить форматирование (Markdown).
- [ ] Убедиться, что документация отражает реальное состояние кода.

## Критерии приемки
- [ ] Все документы в `docs/` актуальны и соответствуют версии v5.6+.
- [ ] Нет битых ссылок.
- [ ] `RULES.md` и `REQUIREMENTS.md` синхронизированы.
- [ ] Архитектурные решения (ADR) отражены в основной документации.
