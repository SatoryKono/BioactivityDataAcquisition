    Часть 2. Выявленные Неточности и Ошибки¶

    2.1. ❌ ЛОЖНЫЕ УТВЕРЖДЕНИЯ (Не Повторять!)¶

    Утверждение Планы Верификация Почему ложно
    "GoldWriter создаёт NoOpTracing — нарушение DI" 1, 2, 3 gold_writer.py:86-89 Null Object Pattern — валидный паттерн (см. CLAUDE.md §2.3). Optional dependency с fallback — НЕ нарушение.
    "bootstrap_pipeline 140+ строк, перегружен" 3, 4 bootstrap.py — 182 строки Делегирует через FilterConfigBuilder.build(), factory.create_runner(). Функция ~115 строк (bootstrap.py:68-182), остальное — импорты.
    "GoldWriter 593 строки" 3 gold_writer.py — 674 строки Неточный подсчёт. Делегирует CSV в CsvExporter, audit в AuditPort.
    "PipelineRunner 173 строки" REFACTORING_PLAN.md runner.py — 166 строк Незначительное расхождение, но показывает устаревшие данные.
    "Тесты не запускаются из-за отсутствия orjson" 1, 2, 4 tests/architecture/ — 20+ файлов Проблема окружения, НЕ кода. При наличии venv тесты работают.
    "Нет архитектурных тестов" 1, 2 tests/architecture/ 20+ архитектурных тестов существуют и работают.
    "CircuitBreaker без метрик" 1, 2, 3 circuit_breaker.py Частично верно для внутреннего CB, но UnifiedHTTPClient интегрирует MetricsPort.
    "MedallionLifecycle без политик" 1 medallion_lifecycle.py:96-102 Использует policy.should_clear_silver/gold.

    2.2. ⚠️ ЧАСТИЧНО ВЕРНЫЕ УТВЕРЖДЕНИЯ¶

    Утверждение Планы Верификация Уточнение
    "MemoryLock без fencing" Все memory_lock.py:31-32 owner_id хранится, но safety guard при записи в Delta отсутствует. Частично верно.
    "Parquet разрешён в sink config" 4 pipeline_config.py:151 format: Literal["jsonl", "delta", "parquet"] — Верно, Parquet разрешён.
    "Нет автоматизации VACUUM" Все medallion_lifecycle.py:150-200 Метод vacuum() реализован, но нет планировщика/cron.
    "print() в коде" Все 13 вхождений Все в docstring/примерах, НЕ в продуктивном коде.
    "NoOp зависимости в writers" 1, 2, 3 bronze_writer.py, gold_writer.py Да, создают NoOp внутри, но это Null Object Pattern — валидный паттерн.
    "mypy 27-32 ошибки" Все mypy — 27 ошибок Верно, требует исправления.

    Проблема Планы Верификация Статус

    3.3. Причины Расхождений¶

    1. Покрытие тестами: План 3 запускал тесты в рабочем окружении, остальные — нет.
    2. mypy errors: План 3 возможно использовал другую версию mypy или конфигурацию.
    3. LOC: Разные методы подсчёта (с/без docstrings, импортов).
    4. Medallion оценка: План 4 учёл Parquet в config (строже), остальные — нет.

    Часть 4. Консолидированный План Рефакторинга¶

    4.1. Приоритет 1 (P1): КРИТИЧЕСКИЕ¶

    P1.1: Исправить mypy ошибки¶

    Статус: Требуется Влияние: Блокирует CI, снижает уверенность в типизации.

    Параметр Значение
    Текущее состояние 27 ошибок mypy --strict
    Целевое состояние 0 ошибок
    Файлы По результатам mypy --strict
    Трудозатраты S-M (1-2 дня)
    Критерий готовности mypy --strict проходит без ошибок

    P1.2: Запретить Parquet в sink config¶

    Статус: Требуется Влияние: Нарушает RULES.md §2.1 (Silver/Gold — только Delta).

    Параметр Значение
    Текущее состояние format: Literal["jsonl", "delta", "parquet"]
    Целевое состояние format: Literal["jsonl", "delta"] для Silver/Gold
    Файлы src/bioetl/infrastructure/schemas/pipeline_config.py:151
    Трудозатраты S (0.5 дня)
    Критерий готовности Валидация отклоняет format: parquet для Silver/Gold

    P1.3: Добавить Safety Guard для блокировок¶

    Статус: Требуется Влияние: Риск split-brain при параллельных записях.

    Параметр Значение
    Текущее состояние MemoryLock хранит owner_id, но Delta writers не проверяют его
    Целевое состояние DeltaWriter/GoldWriter проверяют owner_id перед записью
    Файлы memory_lock.py, delta_writer.py, gold_writer.py
    Риски Ложные отказы при некорректном wiring
    Трудозатраты M (2-3 дня)
    Критерий готовности Тест: запись без lock или с чужим owner_id → ошибка

    4.2. Приоритет 2 (P2): ВЫСОКИЙ¶

    P2.1: Автоматизировать VACUUM (планировщик)¶

    Статус: Частично реализовано Влияние: Накопление мусора в Delta tables.

    Параметр Значение
    Текущее состояние MedallionLifecycleService.vacuum() существует, но нет автоматического вызова
    Целевое состояние VACUUM вызывается после успешного run (настраивается в YAML)
    Файлы medallion_lifecycle.py, runner.py, pipeline_config.py
    Риски Удаление нужных файлов при неверной конфигурации
    Трудозатраты M (2 дня)
    Критерий готовности После run с maintenance.auto_vacuum: true выполняется VACUUM

    Примечание: Конфиг MaintenanceConfig уже существует в pipeline_config.py:92-111.

    P2.2: Унифицировать NoOp паттерн¶

    Статус: Желательно (НЕ ошибка) Влияние: Консистентность DI, упрощение тестирования.

    Параметр Значение
    Текущее состояние Writers создают NoOp внутри конструктора
    Целевое состояние NoOp создаётся в composition layer и инжектируется
    Файлы gold_writer.py:86-89, bronze_writer.py
    Риски Ломающие изменения API
    Трудозатраты M (2 дня)
    Критерий готовности Нет import NoOp* в infrastructure/storage/

    ⚠️ Важно: Это улучшение, не исправление ошибки. Null Object Pattern — валидный паттерн.

    4.3. Приоритет 3 (P3): СРЕДНИЙ¶

    P3.1: Очистить print() из docstrings¶

    Статус: Желательно Влияние: Соответствие grep-проверкам в CI.

    Параметр Значение
    Текущее состояние 13 вхождений print() в docstring/примерах
    Целевое состояние 0 вхождений или whitelist в grep
    Файлы domain/resilience.py, composition/entrypoints.py, infrastructure/config.py и др.
    Трудозатраты S (0.5 дня)
    Критерий готовности grep -r "print(" src/bioetl → 0 или в whitelist

    P3.2: Добавить Redis Lock (опционально)¶

    Статус: Требуется для production с несколькими workers Влияние: Распределённая блокировка для масштабирования.

    Параметр Значение
    Текущее состояние Только MemoryLock (single-process)
    Целевое состояние RedisLock с SETNX+EXPIRE, heartbeat
    Файлы infrastructure/locking/redis_lock.py (новый)
    Риски Зависимость от Redis, сложность тестирования
    Трудозатраты M (3 дня)
    Критерий готовности Integration test с Redis проходит

    Примечание: Для локального development MemoryLock достаточен.

    Часть 5. НЕ Требуют Рефакторинга (Ложные Проблемы)¶

    Предложение из планов Почему НЕ требуется
    "Убрать fallback NoOp из writers" Null Object Pattern — валидный паттерн (CLAUDE.md §2.3)
    "Разбить bootstrap_pipeline на мелкие функции" Уже делегирует через builder/factory, ~115 строк — приемлемо
    "Восстановить тестовый контур" Тесты работают при наличии venv, проблема окружения
    "Добавить fencing token в MemoryLock" owner_id уже хранится; требуется safety guard при записи
    "Добавить метрики в CircuitBreaker" UnifiedHTTPClient уже интегрирует MetricsPort
