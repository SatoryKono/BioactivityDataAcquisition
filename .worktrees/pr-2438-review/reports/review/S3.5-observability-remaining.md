## File-by-File Notes

### observability/ (18 files)

- **`__init__.py`**: Clean re-exports. Imports from both domain (NoOpMetrics, NoOpTracing) and infrastructure modules.

- **`logging.py`** (StructlogLogger): Formal `LoggerPort` adapter wrapping structlog. Methods: `bind()`, `info()`, `warning()`, `error()`, `debug()`, `exception()`. Uses `__slots__` for memory efficiency.

- **`unified_logger.py`** (UnifiedLogger): Enforced Log Schema (RULES.md Section 3.2.1). Mandatory fields: `run_id`, `pipeline`, `stage`. Secret filtering to prevent PII/credential leakage. Stage type validation.

- **`logging_config.py`**: Centralized structlog configuration. JSON and console formatters. One-time initialization pattern.

- **`metrics.py`**: Prometheus metric definitions (Counters, Histograms, Gauges). All metric names follow `snake_case` convention. Labels are bounded with finite cardinality.

- **`prometheus_metrics.py`** (PrometheusMetrics): Implements `MetricsPort`. Registry-based metric dispatching with `HISTOGRAMS`, `COUNTERS`, `GAUGES` dicts. Label normalization with `_normalize_label()` to prevent unbounded cardinality.

- **`server.py`**: `start_metrics_server()` with retry logic, port-in-use handling, and fail-fast mode. Thread-safe with `_SERVER_LOCK`. Prometheus Pushgateway support.

- **`metrics_server_adapter.py`** (MetricsServerAdapter): Thin adapter wrapping `start_metrics_server` for `MetricsServerPort` protocol compliance.

- **`tracing.py`** (OpenTelemetryTracer): OTel TracerProvider with OTLP/Console exporters. Graceful degradation when `opentelemetry` not installed (`OTEL_AVAILABLE` flag). Implements `TracingPort`.

- **`noop_logger.py`** (NoOpLogger): Null Object Pattern for logging (EXC-003 compliant). All methods are no-ops.

- **`circuit_breaker_mapping.py`**: Maps `CircuitBreakerState` enum to numeric values for Prometheus gauge.

- **`anomaly/` (6 files)**: Data quality anomaly detection subsystem.
  - `detector.py`: Anomaly detector coordinator.
  - `monitor.py`: DQ monitoring with baseline tracking.
  - `types.py`: Anomaly detection data types.
  - `detectors/base.py`: Abstract detector base.
  - `detectors/zscore.py`: Z-score based anomaly detection.
  - `detectors/__init__.py`: Detector registration.

### audit/ (2 files)

- **`file_audit.py`** (FileAuditAdapter): Implements `AuditPort`. JSON Lines format. Uses `run_in_executor()` for async file writes (AP-008 compliant). `aclose()` implemented.
- **`__init__.py`**: Module init.

### checkpoint/ (2 files)

- **`local_checkpoint.py`** (LocalCheckpoint): Implements `CheckpointPort`. JSON on local filesystem. Atomic writes via `tempfile` + `os.replace`. Uses domain `serialize_to_json`/`deserialize_from_json`.
- **`__init__.py`**: Module init.

### export/ (3 files)

- **`csv_exporter.py`** (CsvExporter): CSV export with PyArrow. Atomic writes. Complex type serialization (lists/structs to JSON). Deterministic output via column sorting.
- **`dq_report_writer.py`**: DQ report output in YAML format.
- **`__init__.py`**: Module init.

### locking/ (2 files)

- **`memory_lock.py`** (MemoryLock): In-memory lock with TTL expiration. Implements `LockPort`. Background TTL checker task. Fencing token support. Sufficient for local-only deployment (EXC-011 compliant per ADR-010).
- **`__init__.py`**: Module init.

### adr/ (1 file)

- **`fs_adr_service.py`** (FsAdrService): Filesystem-based ADR reader. Regex patterns for ADR metadata extraction. Deterministic file ordering via `sorted()`.

### Root files (2 files)

- **`config_merge.py`**: Deep dictionary merge utility with configurable list handling strategies.

## Findings

### Issues: None (CRITICAL/HIGH)

### Minor Observations (INFO)

1. **`server.py`**: Uses `global _SERVER_STARTED` mutable state. This is an acceptable pattern for singleton server startup but requires `reset_server_state()` for testing.

2. **`tracing.py`**: Graceful import fallback for OTel dependencies. `OTEL_AVAILABLE` and `OTLP_AVAILABLE` flags enable conditional activation -- good pattern for optional dependencies.

3. **`MemoryLock`**: Uses `time.monotonic()` for TTL tracking (deterministic). Background task cleanup on `close()`.

4. **`FileAuditAdapter`**: Uses `datetime.now(UTC)` for audit entry timestamps -- this is legitimate for audit logging (the timestamp records when the audit event occurred, not data processing time).
