## Findings

### Finding F-S4.3-001: Direct Infrastructure Import in observability.py (LOW)

**Rule:** ARCH-001 (import matrix)
**File:** `/src/bioetl/interfaces/observability.py` (line 14)

```python
from bioetl.infrastructure.observability import start_metrics_server
```

The interfaces layer is permitted to import from infrastructure per the ARCH-001 matrix (interfaces can import from all layers). However, the composition layer already provides `ensure_metrics_server_started()` and `maybe_start_metrics_server()` as proper entrypoints.

**Mitigating factors:**
- Interfaces layer CAN import from infrastructure (ARCH-001 allows it)
- The module is a thin re-export layer
- `MetricsServerError` is from domain.exceptions (always allowed)

**Recommendation:** Consider routing through `composition.entrypoints.ensure_metrics_server_started` for consistency with the rest of the interfaces layer. Not a violation, just a consistency improvement.

**Severity:** LOW (-0.25)

```python
finally:

        coro.close()
```

This ensures coroutines are properly closed even on exception.

#### OBS-005: Orchestration Module Reserved (INFO)
