## Цели

* Безопасно удалить пустые директории, каталоги с артефактами компиляции и «однофайловые» директории

* Сохранить работоспособность, соответствие правилам проекта и детерминизм

## Область и защита

* Обход всей структуры: `src/**`, `tests/**`, `docs/**`, `configs/**`, `qc/**`, корень

* Защита пакетов: не удалять верхнеуровневые `src/bioetl/*/` без явного флага; проверять `__init__.py` на экспорт (`__all__`, импорты)

* Игнор: системные (`.DS_Store`, `Thumbs.db`), VCS служебные

## Этап 1. Поиск и идентификация

* Рекурсивный обход

* Классификация директорий:

  * Пустые (нет файлов/поддиректорий, игнорируя служебные)

  * Только `*.pyc` / `__pycache__`

  * Ровно один `*.py` без поддиректорий

* Логирование: `UnifiedLogger` с полями `path`, `reason`, `size`

* Предпросмотр: режим `--dry-run`

## Этап 2. Обработка

* Пустые директории:

  * Повторная проверка «пустоты» → удаление

* Директории с `*.pyc`/`__pycache__`:

  * Удалить все артефакты компиляции

  * Если директория стала пустой → удалить её

* Директории с единственным `*.py`:

  * Проверить наличие файла с тем же именем на уровень выше

  * Если существует: безопасная интеграция содержимого (конкатенация с маркерами и проверкой дубликатов по сигнатурам)

  * Если нет: переместить файл на уровень выше

  * После операции удалить пустую директорию

* Защита от поломки импортов: не перемещать/интегрировать `__init__.py` с явным экспортом без флага `--aggressive`

## Этап 3. Предосторожности

* Резервная копия: архив/копия целевых директорий в `backups/<timestamp>` (атомарная запись)

* Полный журнал: JSON-лог с операциями (до/после, байты, статус)

* Интеграция с VCS: если git активен — перед задачей делать `git status` и запись диффа в отчёт

* Откат: команда `--rollback <timestamp>` восстанавливает из `backups`

## Этап 4. Автоматизация

* Скрипт `src/tools/cleanup_directories.py` со флагами:

  * `--dry-run` / `--apply`

  * `--scope <path[,path...]>` (по умолчанию весь проект)

  * `--exclude <glob>` (множественно)

  * `--include-src` (разрешить `src/bioetl/**`)

  * `--aggressive` (разрешить действия с экспортирующими `__init__.py`)

  * `--backup` / `--rollback <id>`

  * `--log-file reports/cleanup_dirs_<timestamp>.json`

* Повторное использование компонентов из `cleanup_project.py` и `cleanup_packages.py` (обход, логирование, удаление)

## Этап 5. Тестирование

* Импорт-проверка: `python -B -c "import bioetl; print('ok')"`

* Golden-тесты: `pytest -q tests/golden` (без сети), зелёные

* Инвариант классов: `tests/project_rules/class_inventory_baseline.json` остаётся 208

* Дымовой прогон одного пайплайна с `--dry-run` (без записи артефактов)

## Политики и CI

* Продолжать блокировать `*.pyc`/`__pycache__` в pre-commit и CI

* Добавить правило: «однофайловые» папки не допускаются — использовать плоскую структуру

## Риски и их снижение

* Поломка импортов: по умолчанию не трогаем пакеты верхнего уровня и `__init__.py` с экспортом

* Потеря кода при интеграции: делать бэкап и маркировать объединённые блоки; при конфликте — оставить оба с предупреждением

* Windows-локи/права: ловить ошибки, логировать, продолжать обработку остальных путей

## План запуска

1. `--dry-run` по всему проекту, сверка отчёта
2. `--backup` + `--apply` для пустых/pyc/однофайловых
3. Проверки (импорт, golden, классы)
4. При необходимости — точечная обработка `src/bioetl/**` с `--include-src`/`--aggressive`
